		<p>A few moments ago I got reminded of <a href="http://web.archive.org/web/20050309223457/http://blogs.wdevs.com/tybon/archive/2005/01/29/2117.aspx">a book that I read </a>many years ago. Looking at my bookshelves there are various software development books, some new, some old, some out dated, some superceded, some still waiting to be read (Yes, I have a tendancy to buy books faster than I can read them. Also, sometimes I buy a book and my interests or needs change and so it remains unread for months)</p>
<p>So, what books are on my bookshelves:</p>
<p><a title="Photo Sharing" href="http://www.flickr.com/photos/colinangusmackay/614700967/"><img height="675" alt="What's on my bookshelf 1" width="600" border="0" src="http://farm2.static.flickr.com/1261/614700967_52954ac295_o.jpg"></a></p>
<ul>
    <li><strong>Human Computer Interaction</strong> - A book from my university days. It goes unread these days as it is too rooted in theory and not much practical. </li>
    <li><strong>Data Communications, Computer Networks and Open Systems</strong> - Another book from my university days. It too goes unread these days as I have not had much involvement in writing network software, except on a level where I don't really need to deal with the network communication plumbing. Although I did once help to write an NDIS driver. </li>
    <li><strong>Information Modeling and Relational Databases</strong> - It looked promising but I've so far found it to be a very heavy read. I'll eventually get back to it, but for the moment it is staying on the shelf. </li>
    <li><strong>Domain Driven Design</strong> - So far I've not got much past the first couple of pages, but I've only just started reading it. This is one book that I will be finishing sooner rather than later as it is <a href="http://web.archive.org/web/20050309223457/http://xp.roundtripsolutions.com/wiki/index.php/Books">on the reading list </a>of the <a href="http://web.archive.org/web/20050309223457/http://xp.roundtripsolutions.com/wiki/index.php/Main_Page">eXtreme Programming </a>group that I am part of. </li>
    <li><strong>Design Patterns</strong> - It has been a long time since I've read this. I remember at the time thinking that I'd managed to figure out a lot of OO pretty well for myself as I'd been using some of the patterns discussed without having ever come across them in a reference such as this. </li>
    <li><strong>Programming Microsoft Windows with C#</strong> - This was one of the first books on .NET I ever bought. I found it a great book as it kind of joined up the traditional thinking of Windows applications with the .NET Framework. And, of course, just about everyone who has programmed with the Win32 API and done battle with the GDI code knows of Charles Petzold </li>
    <li><strong>Patterns of Enterprise Application Architecture</strong> - Some of this was quite interesting. It is a book I have taken to dipping in and out of rather than trying to read all the way through. However, some of Martin Fowler's references to cricket just lose me. He does liken the rules to Baseball so that Americans and Canadians can understand, but it leaves the poor Scots to just shrug and give up. </li>
    <li><strong>Extreme Programming Explained</strong> - Kent Beck's original work on XP, it is now superceded but I have not yet had a chance to buy the second edition. When I first read this a few years ago I just didn't get it very well. As far as I could see it was all about not needing to document anything and working in pairs. I have since briefly pair programmed and I am won over - it is much more efficient. But, I still feel that most people misinterpret the documentation issue and that really needs to be cleared up. </li>
</ul>
<p><a title="Photo Sharing" href="http://www.flickr.com/photos/colinangusmackay/614701147/"><img height="408" alt="What's on my bookshelf 2" width="600" border="0" src="http://farm2.static.flickr.com/1268/614701147_b18dc0d142_o.jpg"></a></p>
<ul>
    <li><strong>Writing Secure Code</strong>: This is a fantastic book. There isn't much to say on this except that you really must read it. </li>
    <li><strong>Database Modeling</strong>: I found this a little too academic, but at least it gives examples using Microsoft Visio </li>
    <li><strong>Code Complete</strong>,<em> Second Edition</em>: This has to be one of the best books on how to write good code. </li>
    <li><strong>.NET Compact Framework</strong>: I did a little work using the compact framework a while back and this was a good starting reference. However, if you are already familiar with the .NET framework then don't be misled by the bulk of the book - you probably know more than half of what is in this book already. </li>
    <li><strong>Don't Make Me Think</strong>: A great book on how to design good user interfaces on websites. Most of the examples seem common sense, but it is amazing how that just goes out of the window sometimes when deadlines are looming. </li>
    <li><strong>The .NET Developers Guide to Windows Security</strong>: A great book that presents everything in easy to swallow bite sized chunks. That has to be the best thing about the book because a lot of people think about security and shy away from doing it properly because they think it will be hard, and it isn't. And this book shows you how easy it is. </li>
    <li><strong>Professional Software Development</strong>: This one just really validated my reasons for being a software developer and the ways in which to maintain a professional level of conduct. </li>
    <li><strong>Code Complete</strong> (again). This is the original first edition. I suppose I should really get rid of it since I now have the second edition, but I can bring my self to throw out a book that has served me so well. </li>
    <li><strong>Writing Sold Code</strong>: I got this around the same time as the original Code Complete book. Another must have read for people who churn out code. The examples are in C / C++ but I think the issues are just as relevant for other languages. </li>
    <li><strong>Industrial Strength C++:</strong> I don't have much call for this book these days, but the advice was great and if you are a C++ programmer I would recommend that you read it. </li>
    <li><strong>Rapid Development</strong>: It has been a while since I've read this book. The "There are no silver bullets" is one thing that, at the time, I thought I understood, but it has taken experience to actually back that up. There have been times I've looked for quick solutions, but usually they attract the flies like the piles of manure I should have known they were. </li>
    <li><strong>Lean Software Development</strong>: This was previously on the eXtreme Wednesday reading list. You can find a review on it <a href="http://web.archive.org/web/20050309223457/http://blogs.wdevs.com/colinangusmackay/archive/2004/12/11/1470.aspx">here</a>. </li>
</ul>
