<p>Over the course of the last couple of months I’ve blogged a lot about the Task Parallel Library and mentioned a number of statuses that a task can have, but nowhere is a nice handy-dandy chart to show what those statuses are and how the transition from one to another. The green status show the normal line that most tasks will take. The purple and red show alternative paths that may be taken.</p> <p><img style="background-image:none;padding-left:0;padding-right:0;display:block;float:none;margin-left:auto;margin-right:auto;padding-top:0;border-width:0;" border="0" src="http://s3-eu-west-1.amazonaws.com/colinmackay.co.uk/images/parallelisation/2011-06-03-State-transitions-640.png" width="640" height="887"></p> <p>When a task is first created it status is <code>Created</code> – however you will almost never see this. This status only exists when you create a task using its constructor. Most of the time you would create tasks with <code>Task.Factory.StartNew(…)</code></p> <p>When you start a task the status will be <code>WaitingToRun</code> until such time as the task scheduler can actually run the task. For some tasks the transition will be almost instant, for others it will mean a wait while other tasks complete.</p> <p>From <code>WaitingToRun</code> a task can transition to either <code>Running</code> or <code>Cancelled</code>. The latter transition happens if the cancellation token is signalled before the task gets a chance to start. </p> <p>Once a task is running there are three possible exits for it. The normal exit is for the status to transition to <code>RanToCompletion</code> which means that the task completed without incident. The other two exits require exception handling in the calling code. </p> <p>If an error happens that the task cannot (or does not) handle internally then it will transition to <code>Faulted</code> (see <a href="http://colinmackay.co.uk/blog/2011/05/16/tasks-that-throw-exceptions/">Tasks that throw exceptions</a>). The <code>AggregateException</code> will contain details of all the exceptions in <code>Faulted</code> tasks as part of its <code>InnerExceptions</code> collection.</p> <p>If the tasks are cancelled, any task that has not already completed will transition immediately to <code>Cancelled</code>. An <code>AggregateException</code> will contain details of all tasks that were cancelled (whether they had a chance to run or not) with <code>TaskCanceledException</code> inner exceptions. The exception to this is any task that was running already when the cancellation token was signalled and either ran to completion normally, or did not respond correctly to the cancellation request (see <a href="http://colinmackay.co.uk/blog/2011/06/03/cancelling-parallel-tasks/">Cancelling parallel tasks</a>).</p>
