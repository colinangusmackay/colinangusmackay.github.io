<p>Recently, I was refactoring some code and I moved the location of the <a title=".edmx File Overview" href="http://msdn.microsoft.com/en-us/library/cc982042.aspx">.edmx file</a> into a different folder (and new namespace). I updated the code to use the new namespace but when I ran the application a MetadataException was thrown with the message “Unable to load the specified metadata resource.”</p>  <p>When the location of the edmx file changes, so does the connection string. The reason is that an Entity Framework connection string does more than a normal database connection string. So, if you move the edmx file, you also have to update the connection string so that the entity framework can continue to find the resources that the edmx file defines.</p>  <p>The connection string contains details of how the database is mapped to the entities by referencing the CSDL (Conceptual Schema Definition Language), SSDL (Store Schema Definition Language) and MSL (Mapping Specification Language) resources which are defined in the .edmx file, so if the location of the mapping changes then the connection string also needs to be updated so that the entity framework can continue to map the database to the entities.</p>  <p><img style="background-image:none;margin:0 0 0 15px;padding-left:0;padding-right:0;display:inline;float:right;padding-top:0;border-width:0;" border="0" align="right" src="http://static.colinmackay.co.uk/images/ef/2011-07-23-solution-explorer-initial.png" />For example, if you have a little application with two projects, an application project (in this case, the imaginatively names ConsoleApplication2) and class library (named DataAccess). An app.config file will be created for the data access project by the entity framework tools in Visual Studio. Normally that can be copied (or just the connection string entries at least) to the app.config (or web.config) of the main application.</p>  <p>At this point the connection string looks like this:</p>  <p><code>metadata=res://*/Products.csdl|res://*/Products.ssdl|      <br />res://*/Products.msl;provider=System.Data.SqlClient;       <br />provider connection string=&amp;quot;data source=(local);       <br />initial catalog=AdventureWorks;integrated security=True;multipleactiveresultsets=True;       <br />App=EntityFramework&amp;quot;</code></p>  <p>As you can see it makes reference to the Products metadata in the calling assembly (that’s what the * means) which is split into the three resources (CSDL, SSDL &amp; MSL) .</p>  <p><img style="background-image:none;margin:0 15px 0 0;padding-left:0;padding-right:0;display:inline;float:left;padding-top:0;border-width:0;" border="0" align="left" src="http://static.colinmackay.co.uk/images/ef/2011-07-23-solution-explorer-moved.png" />If a ModelEnties folder is created in the DataAccess project and the Products.edmx is moved into the ModelEntities folder then the location of the resource is moved, so the connection string is no longer valid. So, for the change that was just made the connection string needs to be updated to look like this:</p>  <p><code>metadata=res://*/<strong>EntityModel.</strong>Products.csdl|       <br />res://*/<strong>EntityModel.</strong>Products.ssdl|       <br />res://*/<strong>EntityModel.</strong>Products.msl;       <br />provider=System.Data.SqlClient;provider connection string=&amp;quot;data source=(local);initial catalog=       <br />AdventureWorks;integrated security=True;       <br />multipleactiveresultsets=True;App=EntityFramework&amp;quot;</code></p>  <p>I've bolded the bits that have changed.</p>  <p>If you want to quickly get an updated connection string, you can open the edmx file and click in the design area then press F4 (or the menu View&rarr;Properties Window). The window will show Connection String property which can be copied and pasted into the config file.</p>  <p><img style="background-image:none;margin:0 auto;padding-left:0;padding-right:0;display:block;float:none;padding-top:0;border-width:0;" border="0" src="http://static.colinmackay.co.uk/images/ef/2011-07-23-properties-window.png" /></p>
